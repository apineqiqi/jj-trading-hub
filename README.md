# JJ 交易中枢

个人交易中枢 V1.6。目标不是通用行情 App，而是服务 JJ 及不同账户用户的真实持仓、关注池、交易规则和每日决策。

## V1.6 策略中心（第一阶段）

- 每次结构化 AI 策略导入会生成独立、不可变的策略档案，保存账户、适用日期、导入时间、标准化策略快照和格式修复记录。
- 策略条目逐项记录任务与提醒的导入结果：已创建、重复跳过、未选择或未提供价格条件。
- 交易日任务和价格提醒反向关联到准确的策略与原始条目，可一键返回策略中心查看来源。
- 策略中心按账户隔离并按日期、导入时间倒序展示；任务被编辑或删除后，原始策略仍保留，并显示“已修改”或“已移除”。
- V1.6 完整备份包含策略档案；V1.2–V1.5 备份恢复时自动补空策略集合，旧版来源不会被伪造成新策略记录。

仅当新增任务或提醒时建立独立档案；完全重复的导入不会新增档案，也不改变原有来源。同名导入不会自动合并为版本链，每份独立档案从 V1 开始。

当前阶段只做可靠入库、来源追踪与只读核对；策略替换、版本差异、回滚和执行复盘留在后续阶段。策略仍由用户手动粘贴，不连接 AI 账户、不后台监控、不自动下单。

## V1.5 AI 输出格式修复

「交易日 → AI 策略快导」现在可以识别 AI 常见的中文结构引号与全角 JSON 标点，并在解析前进行边界感知修复。

- 只转换 JSON 结构位置的中文弯引号，正文中的“明显强势”等引用保持原样，避免全文替换造成新的语法错误。
- 自动修复成功时显示修复数量，可一键将输入替换成标准 JSON 后再核对。
- 无法安全修复时，错误提示给出行列位置，并继续执行严格字段、日期、账户、价格和去重校验。
- AI 整理提示词增加半角双引号要求，从源头减少不合法 JSON。
- V1.5 备份结构保持兼容，可恢复 V1.2–V1.5 完整备份。

## V1.4 AI 策略快导

在「交易日 → AI 策略快导」复制整理提示词给 AI，再将 JSON 结果粘贴回来。支持 JSON 代码块；原来的普通文字和 ChatGPT 导出导入保持可用。

- 必须确认具体账户和当日适用日期；过期日期、无效价格、模糊区间和未知字段会拒绝导入，保留原文供修正。
- 三阶段任务默认勾选，提醒默认不勾选；提醒需代码、名称与该账户观察池一致。没有价格条件或观察池标的时仍可只导入任务。
- 保留完整执行条件和策略来源；价格提醒只核对阈值，不检查量能等复合条件，不代表成交，不生成风控仓位预算或自动下单。
- 任务按当天阶段、标题和详情去重；提醒按账户、代码、方向和价格去重，含已暂停规则。不会覆盖旧策略，也不重新启用暂停提醒。
- 一次确认导入任务与提醒；写入失败尝试回退并保留预览，回退不完整时明确告警，提醒立即导出页面备份。
- V1.4 备份包含 AI 策略来源，兼容 V1.2/V1.3 备份。

这是本机手动导入，不会连接 AI 账户或自动同步对话更新。只解析明确价格条件；不明确的信息保留为“待确认”任务。修改后的策略可能新增任务或提醒，旧记录需自行清理。

## V1.3 交易计划与价格提醒联动

- 已保存计划可预览并生成入场、止损、目标三条独立提醒；入场方向明确选择突破或回踩。
- 按账户、计划和价格边界去重；只补齐缺失项，不重新启用已暂停提醒、不覆盖原方向。
- 计划卡显示关联数与启用数，提醒中心显示计划来源和已知悉状态。
- 删除计划前确认并清理其关联提醒，手动提醒和其他账户不受影响。
- 标的须在所属账户观察池内；移出后提示缺少行情来源，不伪装成正在有效监控。
- V1.3 备份保留关联信息，兼容 V1.2 备份，恢复时验证账户、标的与计划来源。

提醒采用达到/高于或达到/低于阈值判断，不检测真实穿越事件。三条规则同时独立判断，不意味着入场已成交；价格已满足时可立即提示。使用现有公开延迟行情，关闭页面后不监控，不自动下单。旧计划不会自动启用提醒，请先复核条件。

## V1.2 账户数据与可编辑任务

- 资金与备份入口：按用户维护现金；未录入与零余额明确区分，总览与风控读取同一余额
- 交易日志和账户快照增加用户归属；旧记录保留并逐条确认归属，全账户不混绘资产曲线
- 完整备份包含现金、持仓、观察池、任务、提醒、风控计划和截图；导入前校验和预览，覆盖前二次确认，写入失败尝试回退
- 页面显示实际保存结果，失败时可导出页面内尚未成功保存的数据
- ChatGPT 导出按当前分支读取，默认选最新回复；支持搜索对话、选择具体消息和查看原文
- 每条任务在导入前可编辑标题、完整详情、阶段；按阶段、标题及详情去重，不再限制为 18 项
- 导入后支持单条编辑、阶段移动和删除；移动保留勾选状态，删除同步清理完成记录
- 修复导入后阶段完成样式，风险仪表读取账户组合上限
- 首页旧市场判断和决策表明确标注历史参考
- 沿用现有深色工作台风格，兼容手机端

旧版没有账户归属的记录不会自动分配到 JJ，请在复盘页确认。新账户请先补齐现金。交易日志仍为记录，不会自动改变持仓和现金。备份文件含完整个人数据，请自行妥善保存。

## 核心原则
事实口径未确认时，只给条件判断；任何新增仓位都必须具备触发价、失效价和仓位动作。

## GitHub Pages 部署

本仓库已内置 `.github/workflows/static.yml`。把代码推送到 GitHub 的 `main` 分支后：

1. 打开仓库 **Settings → Pages**。
2. 在 **Build and deployment → Source** 中选择 **GitHub Actions**。
3. 打开 **Actions** 查看 `Deploy Vite site to Pages` 工作流。
4. 部署完成后，Pages 页面会显示可访问网址。

Vite 的 base 为 `/jj-trading-hub/`；发布流程安装锁定依赖、运行数据测试、构建后仅上传 `dist`。

## 本地验证

- `npm test`：对话分支、长条件、阶段分配、策略来源、去重、V1.6 备份兼容和恢复失败回退。
- `npm run build`：类型检查和生产打包。
- `node tests/plan-alerts.ui.test.mjs`：在下述本地服务器启动后运行，验证 V1.3 提醒预览、补齐、暂停去重、账户隔离、刷新保持、删除清理和缺少观察池标的；与原 UI 测试一样需要 Playwright 和 Edge。
- `node tests/strategy.ui.test.mjs`：验证 V1.5 中文结构引号修复、错误定位，以及既有账户确认、提醒主动勾选、任务与提醒去重、来源、取消、写入回退和手机端导入。
- `node tests/strategy-center.ui.test.mjs`：验证 V1.6 策略档案、账户隔离、来源状态、旧版降级提示、来源跳转、刷新保持和手机端布局。
- 浏览器验收：先运行 `python tests/serve.py`，再在已安装 Playwright 的环境运行 `node tests/ui.test.mjs`；使用独立无头 Edge 与测试数据，覆盖账户隔离、任务编辑、恢复和保存失败。截图在被忽略的 `test-results/` 中。
- Windows 受限环境若 realpath 解析祖先目录报 EPERM，可先运行类型检查，再运行 `node --preserve-symlinks --preserve-symlinks-main tests/build-local.mjs`；使用同一 React 插件和 Pages base，保持路径不解析符号链接。
